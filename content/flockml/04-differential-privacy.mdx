# OPFS & Model Streaming

FlockML uses the browser's **Origin Private File System (OPFS)** to cache model weights directly to the user's local SSD — so after the first download, models load in under a second, forever.

---

## The Problem with Reloading Models

<EngineerBlock>
Every time a user refreshes the page, the model would need to be re-downloaded over the network. For a quantized BitNet model, that's still 400MB–1.2GB of weight data. Without caching, that's a 10–30 second wait on every single page load — completely unacceptable for production use.
</EngineerBlock>

<JuniorBlock>
Imagine if Spotify made you re-download every song every single time you hit play. That's what happens without OPFS — your AI model gets re-downloaded from scratch on every page refresh. OPFS is like a local music library saved to your device so it plays instantly.
</JuniorBlock>

---

## How OPFS Works in FlockML

<EngineerBlock>
The browser's OPFS API (`navigator.storage.getDirectory()`) gives each origin a private, sandboxed filesystem partition on the user's SSD. FlockML streams Safetensors shards directly into this partition via `FileSystemWritableFileStream`. On subsequent loads, weights are read back from OPFS at native SSD speeds — completely bypassing the network.
</EngineerBlock>

<JuniorBlock>
Every website gets its own secret folder on your computer that only that site can access — that's OPFS. FlockML stores the AI model files in that secret folder on your first visit. From then on, it loads the AI instantly from your own computer instead of downloading it again.
</JuniorBlock>

```typescript
import { Flock } from 'flockml';

const node = new Flock.Node({ mode: 'inference' });
await node.start();

// First visit: downloads & caches to OPFS
// Every visit after: instant load from local SSD
await node.loadFromHuggingFace('microsoft/bitnet-b1.58-3B');
```

---

## Streaming Safetensors Shards

<EngineerBlock>
Rather than downloading the entire model file before initialization, FlockML streams Safetensors shards progressively. Each shard is written to OPFS and immediately compiled into a WGSL compute pipeline — allowing inference to begin before the full model is on disk. This is similar to progressive JPEG decoding, but for neural network weights.
</EngineerBlock>

<JuniorBlock>
Instead of waiting for the whole model to download before starting, FlockML works like a streaming video — it starts playing (running AI) as soon as the first chunk arrives, while the rest continues downloading in the background.
</JuniorBlock>

```typescript
// Progress events during streaming
node.on('progress', ({ loaded, total, shard }) => {
  const pct = Math.round((loaded / total) * 100);
  console.log(`Shard ${shard}: ${pct}% cached to OPFS`);
});

await node.loadFromHuggingFace('microsoft/bitnet-b1.58-3B');
// Inference already started at ~15% loaded
```

## Cache Invalidation

<EngineerBlock>
FlockML stores a SHA-256 hash of each model version alongside the cached weights in OPFS. On load, it fetches only the remote model's manifest (a few KB) and compares hashes. If the model version changed, the stale shards are evicted and re-downloaded. If the hashes match, the full OPFS cache is used — zero network bytes transferred.
</EngineerBlock>

<JuniorBlock>
FlockML keeps a tiny "fingerprint" of the model saved next to it. On every page load, it quickly checks if the fingerprint on the server still matches the one saved locally. If yes — instant load from your computer. If the AI model was updated — it downloads just what changed, like a software update.
</JuniorBlock>

| State | Network cost | Load time |
|---|---|---|
| First visit | Full model download | 10–30s |
| Returning (no update) | ~2 KB manifest only | < 1s |
| Returning (model updated) | Changed shards only | 3–8s |

## Storage Quota & Cleanup

```typescript
// Check how much OPFS space is being used
const { usage, quota } = await navigator.storage.estimate();
console.log(`Using ${(usage / 1e9).toFixed(2)} GB of ${(quota / 1e9).toFixed(2)} GB`);

// Manually evict all cached models
await node.clearOPFSCache();
```

Most browsers grant **5–10 GB** of OPFS storage per origin on desktop. FlockML will warn users before evicting old cached models to make room.
