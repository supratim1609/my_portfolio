### Rivet: The Fastest Dart Backend Framework — And the Start of a True Full-Stack Dart Future

Backend frameworks come and go. Most of them follow the same story: routing, middleware, a few helpers, and some marketing on top. Very few dare to challenge the fundamentals of how developers build modern applications.

Rivet started because I was tired of the same recurring problem in the Flutter/Dart ecosystem:

> **_Why do Flutter developers need to learn Node.js, Python, Go, or Java just to build a backend?_****_Why can’t we build_ everything _in one language — end to end — without sacrificing performance or developer experience?_**

When I looked around, the answer was obvious: nothing truly solved this. **Shelf** is minimal. **Serverpod** is heavy and opinionated. **Node.js** isn’t type-safe. **Go** doesn’t integrate with Flutter. **NestJS** is beautiful, but it’s locked to the JavaScript world.

So I built Rivet: a backend framework that’s not only **4.15x faster than Shelf**, but also designed with a much bigger goal:

> **_One language. One framework. Backend to mobile.  
> For Flutter developers. For Dart developers.  
> And soon — to compete directly with Node.js, NestJS, Express, and the entire JavaScript backend ecosystem._**

This blog post is the story of how we got here, where Rivet is going next, and why v2.0 might reshape what “full-stack Dart” means.

### 1\. Full Decorator Support — NestJS but for Dart

Developers have been asking for this from day one.

And Rivet v2.0 delivers:

@Auth()

### Why Rivet Is Fast — The Technical Breakdown

### 1\. Trie-Based Router

Regex-based routing is slow.  
Trie routing is O(k) where k = path length.

Less branching, faster lookup.

### 2\. Minimal Overhead Core

No unnecessary abstractions.  
No deep middleware chains.  
No reflection-heavy dynamic dispatch.

### 3\. Multi-Core Support

Rivet automatically spawns multiple isolates to use all CPU cores.

Shelf doesn’t do this by default.

### 4\. Zero-Copy Parsing

Minimal allocations, more stable performance.

### 5\. Batched Microtask Scheduling

Requests are processed in microtask batches → fewer context switches.

### 6\. Streams Everywhere

Rivet uses Dart Streams internally for maximum throughput.
